# MoscowTab — магазин в Telegram (Mini App)

Каталог и корзина внутри Telegram. Покупатель нажимает «Заказать» — бот пишет
состав заказа ему в чат и присылает тот же заказ администратору с кнопкой
«Написать клиенту». Товары добавляются прямо в приложении: тот, чей Telegram ID
указан в `ADMIN_IDS`, видит вкладку «Админ».

Витрина одна — Mini App. Бот только приглашает в него: на любое сообщение
отвечает кнопкой «Открыть магазин» и ставит такую же кнопку в меню рядом с
полем ввода. Приложению нужно, чтобы телефон сам открыл наш домен.

Кроме каталога есть рекламная лента на главной, промокоды со сроками действия
и лимитом применений, кадрирование картинок перед загрузкой, подробная карточка
товара и форма доставки в корзине.

Хостинг полностью бесплатный: Cloudflare Workers (бэкенд, бот и раздача фронта),
D1 (база), фото хранятся в самом Telegram по `file_id` — ни диска, ни бакета,
ни платёжной карты.

```
worker/src/bot/   вход в Mini App: приветствие с кнопкой запуска
worker/src/       API Mini App, проверка подписи Telegram, логика заказов
frontend/         React + Vite: каталог, корзина, админка приложения
```

## Как авторизуется админ

Telegram отдаёт мини-приложению строку `initData`, подписанную HMAC-SHA256 на
ключе от токена бота. Worker проверяет подпись (`worker/src/auth.js`) и берёт
оттуда user id. Подделать подпись, не зная токена, нельзя — поэтому отдельный
логин и пароль не нужны: админ это просто id из `ADMIN_IDS`.

## Настройки

| Переменная | Где задаётся | Что это |
|---|---|---|
| `BOT_TOKEN` | секрет: `npx wrangler secret put BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) |
| `ADMIN_IDS` | `wrangler.toml` → `[vars]` | Telegram ID админов через запятую |
| `ORDER_CHAT_ID` | `wrangler.toml` → `[vars]` | куда слать заказы; пусто — в личку первому админу |
| `SHOP_NAME` | `wrangler.toml` → `[vars]` | заголовок в шапке |
| `MINI_APP_URL` | `wrangler.toml` → `[vars]` | адрес приложения для кнопок бота |
| `DEV_MODE` | только локально | `1` — пускать без Telegram под фейковым админом |

## Локальный запуск

```bash
cd frontend && npm install && npm run build      # фронт собирается в frontend/dist
cd ../worker && npm install
npx wrangler d1 execute moscowtab --local --file=./schema.sql
npx wrangler d1 execute moscowtab --local --file=./seed.sql     # демо-товары, по желанию
npx wrangler dev --var BOT_TOKEN:тест --var DEV_MODE:1
```

Открыть http://localhost:8787 — `DEV_MODE=1` пускает без Telegram и делает
тебя админом. Фронт при правках нужно пересобирать (`npm run build`).

### Проверки

```bash
# 1. подставной Telegram API — ловит исходящие вызовы бота

# 2. worker с боевой авторизацией и моком вместо Telegram

  --var TELEGRAM_API_BASE:http://localhost:9099 --var WEBHOOK_SECRET:testsecret

# 3. проверки
node tests/api.mjs                              # подпись, права, остатки, заказы
TG_LOG=/tmp/tgcalls.jsonl node tests/bot.mjs    # приветствие бота и кнопки запуска
```

## Обновление базы

`schema.sql` создаёт таблицы с нуля и на существующей базе новые колонки не
добавляет — для этого лежат разовые миграции:

```bash
cd worker
npx wrangler d1 execute moscowtab --remote --file=./migrations/0001_delivery_and_promo_limit.sql
```

Повторный запуск падает с `duplicate column name` — значит, миграция уже
применена. На свежей базе миграции не нужны.

## Деплой на Cloudflare

```bash
cd worker
npx wrangler login                                  # один раз
npx wrangler d1 create moscowtab                    # id из вывода вписать в wrangler.toml
npx wrangler d1 execute moscowtab --remote --file=./schema.sql
npx wrangler secret put BOT_TOKEN                   # вставить токен бота
npx wrangler secret put WEBHOOK_SECRET              # любая случайная строка
cd ../frontend && npm run build
cd ../worker && npx wrangler deploy
```

Wrangler выдаст адрес вида `https://moscowtab.moscowtab.workers.dev`.

## Привязать к боту

Бот подключается вебхуком:

```bash
curl -X POST "https://api.telegram.org/bot$BOT_TOKEN/setWebhook" \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://moscowtab.moscowtab.workers.dev/tg",
       "secret_token":"тот же WEBHOOK_SECRET",
       "allowed_updates":["message","callback_query"]}'
```

Кнопку меню бот ставит сам при первом сообщении, беря адрес из `MINI_APP_URL`.
Задать её вручную (например, другой адрес для проверки):

```bash
BOT_TOKEN=... python3 set_menu_button.py https://trydokli.ru
```

Дефолтную кнопку для всех чатов сразу можно задать только в BotFather:
Bot Settings → Menu Button. Через API она не переопределяется.

## Что важно знать

- **Оплата.** Telegram Payments и платёжные провайдеры не пропускают табачные
  товары — поэтому оплаты в приложении нет: заказ уходит в чат, дальше
  договариваетесь напрямую.
- **Бот должен быть запущен покупателем.** Если человек открыл Mini App, но
  никогда не нажимал `/start`, бот не сможет написать ему в личку — заказ всё
  равно создастся и придёт админу, в ответе API будет `customer_notified: false`.
- **Цены и остатки считает сервер.** Корзина клиента передаёт только id и
  количество; суммы берутся из базы, остаток списывается условием `stock >= qty`,
  так что две одновременные покупки последней пачки не уведут склад в минус.
- **Фото.** Админ загружает картинку → Worker отправляет её боту → в базе лежит
  `file_id`, отдаётся через `/photo/<file_id>` с кэшем на неделю.
- **Возрастной гейт** — экран 18+ перед каталогом, отметка хранится в браузере.
- **Поведение окна.** При запуске просим полный экран и отключаем вертикальные
  свайпы, чтобы случайное движение не сворачивало магазин. Обе возможности из
  Bot API 8.0: на старых клиентах вызовы молча пропускаются и остаётся обычный
  `expand()`. В полном экране отступы сверху берутся из
  `--tg-safe-area-inset-top` и `--tg-content-safe-area-inset-top`, иначе шапку
  перекрывают кнопки Telegram.
- **Ярлык на экране телефона.** Кнопка «На экран» в шапке показывается, только
  если клиент это умеет и ярлыка ещё нет.
- **Кадрирование.** Картинка режется в браузере до отправки: товары 1:1, баннеры
  16:9. На сервер уходит уже обрезанный JPEG, поэтому карточки в каталоге и
  лента на главной одного размера, а трафик меньше.
- **Реклама.** Лента баннеров над каталогом — горизонтальная прокрутка с
  прилипанием. Только картинки, без переходов: добавляются в админке.
- **Промокоды.** Процент или фиксированная сумма, действуют в интервале дат
  включительно, регистр не важен. Скидку считает **сервер** — и при проверке
  кода, и при оформлении: клиент присылает только строку кода. Скидка никогда
  не превышает сумму заказа. У кода есть лимит применений (`0` — без
  ограничения): применение занимается тем же условием в `UPDATE`, что и в
  выборке, поэтому два одновременных заказа не уведут счётчик за лимит. Если
  заказ откатился из-за разобранного товара, применение возвращается обратно.
- **Доставка.** В корзине покупатель заполняет имя, телефон (или другой
  контакт) и адрес — без них заказ не принимается; комментарий по желанию.
  Данные уходят админу в сообщение о заказе и хранятся в `orders`. Введённое
  запоминается в браузере, чтобы не набирать заново.
- **Карточка товара.** На карточке в каталоге сверху слева кружок «!» —
  открывает описание, бренд, вкус, фасовку и остаток отдельным экраном, чтобы
  сетка каталога оставалась короткой.
- **Корзина не теряется.** Состав лежит в `localStorage`: Telegram выгружает
  страницу при сворачивании. При загрузке каталога исчезнувшие товары из неё
  выкидываются, а количество подрезается под остаток.
- **Домен.** `*.workers.dev` у части мобильных операторов не открывается,
  поэтому приложение живёт на своём домене `trydokli.ru`, привязанном к тому же
  Worker как Custom Domain. Вебхук остаётся на `workers.dev`: до него
  достукивается сам Telegram, блокировки провайдера ему не мешают.
